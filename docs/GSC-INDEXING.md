# Request Google Search Console indexing

Use a signed-in Google account with access to the URL-prefix property `https://br413.github.io/`. Google verification is emitted from `metadata.verification.google` in `app/layout.tsx`; the retained root `index.html` is not the deployed homepage. See [SEO setup](SEO-SETUP.md) if verification needs attention.

## Steps

1. Open [Search Console](https://search.google.com/search-console) and select `https://br413.github.io/`.
2. Check that the deployed page loads and its canonical URL points to the intended root-site URL.
3. Open **URL Inspection**, enter a changed page's full URL, and use **Test live URL** if needed to check crawlability.
4. Choose **Request indexing** for the changed page.
5. Confirm [https://br413.github.io/sitemap.xml](https://br413.github.io/sitemap.xml) is submitted in **Sitemaps**. The generated [robots.txt](https://br413.github.io/robots.txt) also references it.

An indexing request does not guarantee indexing, and repeated requests for the same URL do not speed it up. See Google's [recrawl guidance](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl) and [sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview).

## Updating SEO files

Change the relevant Next.js page metadata or `lib/data.ts` content, and update sitemap behavior in `app/sitemap.ts` or crawler rules in `app/robots.ts` when required. Rebuild and push the reviewed changes to `main`; the Pages workflow publishes the generated files.

Do not manually edit the retained root `sitemap.xml` or `robots.txt` to change the deployed site. Article and cover updates alone do not require changing unrelated page dates.
